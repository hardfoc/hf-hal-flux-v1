enum class manifold_valves::ProportionalId : uint8_t

WH bench precision proportional valves driven by the TLE92466ED.

Each channel has full closed-loop current control with PWM frequency, optional dither, slew-rate control and rich per-channel diagnostics.

Channel mapping (Flux V1 board, TLE92466ED OUT0..OUT5)

 |------|--------|---------------|------------------------------------|
 | 0    | FRV    | VSO MaxFlow   | Flow Regulator Valve               |
 | 1    | SPV_L  | VSO standard  | Supply Pressure Valve — low range  |
 | 2    | FCV    | VSO MaxFlow   | Flow Control Valve                 |

 | 4    | SPV_H  | LM-Pro        | Supply Pressure Valve — high range |

◆ SolenoidDriveMode

enum class manifold_valves::SolenoidDriveMode : uint8_t
strong

How a MAX22200 channel is driven.

  • BinaryHitHold — classic on/off solenoid. The first apply pushes a fixed (hit_ma, hold_ma, hit_time_ms) profile via ValveManager::ConfigureSolenoidCdr; subsequent applies just toggle EnableChannel / DisableChannel.
  • VariableCurrent — the same MAX22200 channel is used to drive a proportional valve. We push hit = hold = target_current with hit_time = 0 (no hit phase) every time the requested position changes, giving 7-bit (~0.8 % of IFS) current resolution. This is coarse compared to the TLE92466ED but more than sufficient for valves like SEV that don't need true linear control.

◆ SolenoidId

enum class manifold_valves::SolenoidId : uint8_t
strong

WH bench valves driven by the MAX22200 (octal solenoid driver).

  • OLV_1 / OLV_2 — outlet cartridge solenoids (Parker C21).
  • VEV — vent solenoid (Parker C15).
  • ORV / AVV — overflow / air-vent solenoids (Parker C15).
  • GDV — gas/drain miniature solenoid (Parker SRS, 0.5 W coil).
  • SEV — proportional valve driven via the MAX22200's 7-bit CDR ladder for coarse opening-percentage control. SEV does not require TLE-class precision on this bench so it lives on the MAX22200 to free up a TLE channel.
Channel mapping (Flux V1 board, MAX22200 OUT0..OUT7)
The enumerator value is the array index into kSolenoidMap. The manager_channel field of each map entry below names the actual MAX22200 hardware channel — see the table for the bench wiring.
OUTn Valve Model Notes
0 (none) — Spare; intentionally left unmapped.
1 OLV_2 C21 BinaryHitHold
2 VEV C15 large BinaryHitHold
3 OLV_1 C21 BinaryHitHold
4 SEV VSO 24V VariableCurrent (CDR pseudo-prop)
5 GDV SRS 0.5 W BinaryHitHold (low-current coil)
6 ORV C15 large BinaryHitHold
7 AVV C15 large BinaryHitHold
Note
Adding a new MAX22200-driven valve:
  1. Add an enumerator above Count here.
  2. Add a row in kSolenoidMap (below) referencing a model spec.
  3. Bump kNumSolenoids automatically (it tracks the enum size).

Top-level operational state of a valve as observed by the manager.

Compile-time map of solenoid IDs → MAX22200 channels.

Bench wiring (MAX22200 OUT0..OUT7): OUT0 → unconnected (spare) OUT1 → OLV_2 (C21) OUT2 → VEV (C15) OUT3 → OLV_1 (C21) OUT4 → SEV (VSO 24V — pseudo-proportional via CDR) OUT5 → GDV (Parker SRS 0.5 W miniature) OUT6 → ORV (C15) OUT7 → AVV (C15)

Array order MUST match SolenoidId enumerator order (used as O(1) index).

.dither_frequency_hz = 50,
.supports_dither = true,
}

LM-Pro 24 V coil — Table 1: 148 Ω, 115 mA full flow.

LM-Pro is a linear-motor design and does NOT mechanically benefit from dither, but the TLE92466ED's FB_I_AVG / FB_DC averager only runs once Tmeas has been established — and Tmeas is derived from the dither timing. We therefore enable a tiny "telemetry-grade" dither (1 mA at 50 Hz). It's far below the LM-Pro's mechanical bandwidth so it is inaudible / imperceptible at the plunger but it keeps the chip's feedback registers ticking. See bench notes in hf-tle92466ed-driver/docs/troubleshooting.md.

Parker SRS Miniature Pneumatic Solenoid — 24 V, 0.5 W coil.

Per Parker SRS datasheet (10 mm manifold-mount, 3-port direct-acting poppet). The "Power Options" column lists 0.5 W and 1.0 W variants:

  • 0.5 W @ 24 V → I = P / V = 20.8 mA, R = V² / P = 1152 Ω.
  • 1.0 W @ 24 V → I = 41.7 mA, R = 576 Ω.

The bench uses the 0.5 W variant by default (Models 10, 13, 16). The datasheet explicitly recommends "spike and hold or PWM electrical control" for further power reduction, so a BinaryHitHold profile fits well.

Response: < 30 ms cycling (datasheet "Performance Characteristics").
