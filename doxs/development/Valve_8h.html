Detailed Description

Base class for all WH bench valves — atomic state, lock-free API.

@Browser A Valve instance lives for the entire program life and is shared between three asynchronous parties:

  1. Application / control-loop threads — push setpoints (RequestPosition, RequestState) and read back the latest actual state via lock-free atomic loads.
  2. Any writer that calls Apply() to flush the pending setpoint to the driver IC via FLUX_API.valves. There is no dedicated dispatcher thread; writers (the manifold control loop, mode-thread setpoints, console valve commands, calibration / leak controllers, the verified-stop helper) all call Apply() themselves, serialised by the HAL ValveManager SPI mutex.
  3. SafetyMonitorThread, which periodically calls OnDiagnostics() on every valve to aggregate fault flags from the driver IC into the per-valve snapshot + sticky fault counters.

The base class only owns shared state. Each subclass (SolenoidValve, ProportionalValve) implements Apply() and OnDiagnostics() against the Flux::ValveManager API (FLUX_API.valves).
