Detailed Description

Singleton managing all board communication channels for Flux V1.

Design decisions vs. Vortex:

  • Fixed compile-time device counts (no heap vectors for device tracking).
  • SPI bus + two devices known at link time.
  • No I²C bus (GPIO not routed / unused on this product).
  • CAN bus available for external controllers (e.g. compressor).

◆ AcquireUart()

BaseUart * CommChannelsManager::AcquireUart ( const UartAcquireConfig &  cfg)
noexcept

Acquire (lazy-create + cache) a UART on the given ESP32 port.

First call wins the configuration; subsequent calls with the same port_number return the cached BaseUart& and ignore further config requests (a warning is logged if the new config differs from what was cached). Returns nullptr on configuration error.

RS-485 half-duplex is enabled automatically when rts_pin >= 0.

◆ AcquireUsbSerialJtag()

BaseUsbSerialJtag * CommChannelsManager::AcquireUsbSerialJtag ( const hf_usb_serial_jtag_config_t &  cfg = {})
noexcept

Lazy-acquire the built-in USB Serial/JTAG controller.

The ESP32-S3 has exactly one USB Serial/JTAG block, hard-wired to GPIO19/20 — there are no pins or baud rate to configure, only the driver-side TX/RX ring sizes. The first caller wins the ring sizes; subsequent calls reuse the same BaseUsbSerialJtag&.

If the IDF console (CONFIG_ESP_CONSOLE_USB_SERIAL_JTAG=y) has already installed the underlying driver, this just shares it — both printf / ESP_LOG and our wrapper push to the same TX ring.

Parameters
cfgRing buffer / policy configuration (defaults are sane: 256-byte TX, 256-byte RX). Honoured only on the first call.
Returns
Pointer to the cached BaseUsbSerialJtag (=== EspUsbSerialJtag), or nullptr if the host platform has no USB Serial/JTAG block or driver install failed.
