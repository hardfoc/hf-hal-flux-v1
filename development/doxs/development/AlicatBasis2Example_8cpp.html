Detailed Description

Comprehensive Flux V1 example exercising the Alicat BASIS-2 driver and AlicatBasis2Handler over an ESP32-S3 UART configured for RS-485 half-duplex.

Walks through every public handler entry point so you can use this file as a working "cookbook" for embedding BASIS-2 mass flow meters / controllers in a Flux-based project:

  1. Bring up the Flux HAL (so loggers / Flux::GetInstance() are alive even though this example only needs UART).
  2. Construct a single EspUart on UART1 with TX=GPIO17 and RX=GPIO18 (override at the top of the file). The UART is then switched to HF_UART_MODE_RS485 so ESP-IDF drives DE/RE automatically through the RTS pin.
  3. Multi-baud discovery + normalisation:
    • Sweep every supported BASIS-2 baud rate (4800/9600/19200/38400/57600/115200) using DiscoverAcrossBauds() so devices that were previously reconfigured aren't invisible.
    • Run NormalizeBusBaud(target) to bring every discovered device onto a single baud (38400 by default — flip cfg::kNormalizeBus off to skip).
    • Re-run a single-baud Discover() at the target baud as a sanity check.
  4. For every present address build a dedicated AlicatBasis2Handler that shares the same bus mutex; read identity (firmware/serial/units/full-scale).
  5. Configuration walkthrough exercising every public write entry point: gas, reference temperature, averaging, totalizer mode, comm watchdog, autotare, max-setpoint ramp, totalizer batch, setpoint source, setpoint, tare, totalizer reset.
  6. Quick measurement-window demo — configure trigger, start a 200-sample window, read back min/max/avg.
  7. Steady-state periodic poll loop: every iteration prints ReadInstantaneous() for every present instrument and once per minute re-reads identity to confirm the link is healthy.

This file is the canonical reference for projects that want to embed BASIS-2 sensors as ground-truth digital readbacks alongside an ADS7952 sampling their analog output for the live control loop.

Note
The example is defensive: every Modbus call's error code is logged but the loop continues, so a meter (rather than a controller) — which legitimately rejects setpoint writes with ModbusException — does not abort the test.
