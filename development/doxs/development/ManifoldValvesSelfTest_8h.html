Detailed Description

Boot-time self-test that exercises every WH bench valve in sequence and surfaces any per-valve diagnostic the driver IC reports.

Mirrors the per-driver test patterns we built up while bringing up the MAX22200 and TLE92466ED on the Flux board:

  • Solenoids (MAX22200): toggle ON/OFF a few times with settling
    • diagnostic-poll windows in between, exactly like the c21_cycle_test in the MAX22200 driver examples folder.
  • Proportionals (TLE92466ED): ramp from 0 to full flow and back while sampling the live FB_I_AVG telemetry, exactly like the lm_pro_cycle_test in the TLE92466ED examples folder.

The self-test does NOT bypass the existing ManifoldValvesControlThread / ManifoldValvesDiagnosticsThread; it is layered on top of them. It sets the per-valve target via RequestPosition (the same lock-free API any control loop would use) and waits for the control thread to push it. Diagnostics are read back through Snapshot() after the diagnostics thread has had at least one full pass.

The user can only physically connect ONE valve to the manifold at a time on this bench, so the self-test pauses between valves for kInterValvePauseMs to let the operator move the connection.

Per-valve enable masks let the operator skip valves that are not currently fitted — see SelfTestPlan below. The default is "test every solenoid then every proportional".
